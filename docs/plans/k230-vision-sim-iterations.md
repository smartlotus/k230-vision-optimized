## 2　先固定相机与夹爪的真实运动关系

~~~text
底盘
└─ 云台绕竖轴转 θ
   └─ 升降板沿竖直方向移动 h
      ├─ 水平蓝杆 → 竖直末端支架 → 固定向下的摄像头
      └─ 与蓝杆平行的水平导轨 → 滑块伸缩 s → 可开合的夹指及夹持中心 TCP
~~~

- **用户确认的关系。** θ、h 同时带动相机和夹爪；s 只改变夹爪相对镜头的位置。夹爪约低于镜头 80 mm，在参考姿态下比镜头略靠外。长度大致相当。开合单独作为状态。重点复现光心、夹持中心、遮挡和运动顺序，可用方块、滑块、两片夹指表示机构。
- **沿用 R2。** 行驶光心 400 mm，范围 100–400 mm，垂直拍右侧地面，纵向正对右轮中点，水平回转半径 180 mm。外伸 116 mm、对角视场 96°、停车光心高度 330 mm 属于模拟设定。相机观测角色须有来源标识；场景保留可替换的前视扫码机位。
- **无需等待的初始参数。** 参考位 s=0 时 TCP 向外超出光心 15 mm，初设滑块相对行程 −25 至 +35 mm、张开内距 60 mm，单指厚 4 mm。上下偏置在 70/80/90 mm、参考外移在 5/15/25 mm 中采样。这些是试验假设。夹具可达性由工作面和限位扫描决定；判断不可达时进入重停车/换姿态分支，不靠拉长手臂强行通过。
- **两种虚拟下位机反馈都跑。** 一种反馈带噪声和延迟的 θ、h、s 数值；另一种只反馈回零、行驶/抓取/叠放高度、收回/工作/伸出、运动中、到位或限位。档位模式使用该档的示教参考点和误差范围；无法确定当前位置时先回到已知档位。夹指中点可见时允许用 RGB 估计 TCP 投影，再与最新机构反馈核对。
- **几何自检。** 只伸滑块时，相机矩阵与静止背景投影保持，夹指在画面中移动；只升降时相机与 TCP 高差保持；只旋转时二者绕同轴。逐帧验证工作行程、收拢包络、伸出扫掠、装仓和不同高度的净空。名义最低光心 100 mm 时 TCP 约离地 20 mm，最低指尖另算。升降防碰地由高度、限位与净空模型处理。右侧近线由路面视觉处理。

**对现有实现的具体改造点。** `build_scene.py` 里的 TASK、COLORS、两处转盘顺序、固定二维码图片和默认 `build_round()` 应统一使用场景配置。`round_plan.py` 已能接受任务码和起点。`vehicle.py` 的云台/升降树下新增导轨与夹指。`live_round.py` 目前在 MOVE/RETURN 切到时间轴的已知位姿；新闭环需根据运动反馈推进并重新渲染。`servo_trial.py` 改用随 θ/h/s 和工作面更新的夹爪参考点。已有 `vision/lane.py` 的双边界估计和 RoadNet 可作对照，右侧单边界单独评分。给每个新入口保留 R2 兼容回归配置。官方评分细则以本地 PDF 为准，缺失计分观测时把这一评分项标为 UNKNOWN。


## 5　K230 与虚拟 STM32 的接口

**先把“偏了多少”和“哪个机构该动”约定清楚。** 沿用 R2 车体系，+X 向车右、+Y 向车头、+Z 向上。原始画面宽 W、高 H，顶面中心为 (u,v)，调试用屏心误差为 (u−W/2, H/2−v)，向右、向上为正。640×360 的屏心是 (320,180)。抓取时另算 (u−u_ref, v_ref−v)，其中参考点是当前 θ/h/s 下夹持中心在目标工作面上的投影。两项分别命名，带单位和坐标系。例：顶面在 (330,180)，夹持参考点也在 (330,180)，屏心横偏为 +10 px，而夹取横偏为 0。仿真用已知相机参数和关节反馈算参考点；实机以后可换成按档位示教的参考点表。单轴小步试探建立像素变化与轴方向的对应，正负扰动各跑一次；右展后仍以车体系解释“向左”。

**二层放置的释放条件。** 先核对槽号和第一层颜色，再把第一层顶面与被夹物中心投到同一车体 XY。比较水平残差，连续稳定、机构已到允许释放高度且观测仍有效时才张爪。底块即将被遮住时锁存位置和时间，之后若车、底块或参考坐标可能移动且无法更新，先撤回重观测。撤爪后独立裁判检查是否仍为同色双层。扫码要记下具体机位；若某配置只有向下相机且码面不可见，预期结果是扫码不可观测，另列前视扫码配置的成绩。

| 工作模式 | 图像与反馈 | K230 的输出及验证 |
| --- | --- | --- |
| 行驶 | 右展且升到行驶位、路段意图、可选模拟里程计 | 正常、建议底盘左横移、边界丢失/未知。危险与恢复用不同门槛；底盘左移后用新帧验证右侧间隙确实增大 |
| 寻找与对准 | 目标颜色/槽、曝光对应的 θ/h/s 反馈、新 RGB | 目标中心、该高度夹持参考点、像素误差与建议作用轴。分别命名云台顺/逆时针、导轨伸/缩和底盘左右；每次小步后重新观测。当前轴无法消除的残差转给另一轴，并限制在同一目标上反复换轴的次数 |
| 升降切换 | 行驶/取料/加工/叠放档位、运动中、到位或限位 | 机构未停稳时丢弃此前稳定记录；到位后重采样。源图像素使用左上原点，u 右、v 下。角度、档位、工作面或 TCP 参考点改变均重新绑定 |
| 夹取和释放 | 张合、试提、仓位占用、释放、撤爪以及接触回执 | 区分视觉已对准、已握住、已入仓、已放稳。上下物料高度不同，使用各自高度的射线/平面换算；撤爪后重新观察，以接触裁判与独立可见证据评分 |

复用 Observation 的 camera_id、frame_id、timestamp_ms、target_id、station、plane、image_profile、coord_frame、u_px/v_px、stable、is_simulated、target_pose_valid。模拟行为通道另拟 `actuator, direction, error, unit, observation_id, action_id, valid_until`。示例为 `BASE/BODY_LEFT`、`TURRET/CCW`、`SLIDE/EXTEND`、`LIFT/OBSERVE_PRESET`。模拟时钟与发送端/接收端的时基要区分。本地 PC 可直接回放同一消息到 Python 和现有 C 解码测试。沿用 v1 中 C/V/A 及材料 S 原有语义，新增反馈先走独立版本的本地通道。真实 V 的 IMAGE_PX 不填毫米，仿真毫米带模拟来源，轴/方向不藏进诊断 reason 字符串。

每轮都保存一段可读交互，例如“目标相对 TCP 沿轨向外 → 导轨伸出 → 收到动作 ID 的到位 → 新帧误差缩小 → 试提 → 仓内确认”。另存失败对照“执行成功、DONE 丢失 → UNKNOWN → 查询场景可提供的反馈 → 核清后才能记账”。没有可核查反馈的场景按预期挂起该动作，到本场时限后以故障终态结束，释放 worker。仅裁判能读取物块真值、精确位姿、理想接触点和不可见区域；推理和决策不得导入裁判数据。模拟上报给控制器的关节量、里程计和限位是有标识的传感输入。

## 6　场景划分、训练与版本选择

1. **固定场景家族再跑。** 默认 36 组开发、12 组验证、12 组最终封存，共 60 组可完成竞赛场景；首批 6 组冒烟计入开发。困难题/故障题另建清单并预写预期行为。每组覆盖整段轨迹和该轨迹的派生帧。同一基础布局/摆放与相邻镜头的近重复样本不得跨组。核对两起点、六种颜色、三槽排列、不同合法布局、照明、转盘方向、停位和夹指遮挡的覆盖。布置变量以比赛规则为界；专门制造的不可达/不可通行场景进入负例清单。若新布局改了障碍，渲染几何、足迹/碰撞裁判和路径可达性同时更新。
2. **每场固定版本，每批决定改什么。** 冻结 TopFaceNet、RoadNet、二维码与读环算法建立基线。自动把失败分类为目标漏检/错色、边界误报、中心定位偏差、不可达、观测过期、控制符号错、物理释放失败等，保留不能归因项。动作符号和夹具工作点引起的偏差先修相应模块，再用相同输入比较。
3. **只在有证据时训练。** 每开发组先抽约 20–40 个不同姿态。自动核对 RGB/真值相机矩阵、可见性、平面、颜色、遮挡、标签摘要及近重复项，保存叠图作可追溯记录。道路优先复用 `fit_adapter.py` 的二分类层；顶面系统性退化时复用 `B/research/topface` 的正式权重与训练入口微调，保留原数据分布。候选记录输入、样本数、随机种子、训练预算、验证集度量和导出 SHA。冻结评估与候选训练按本地能力运行。基线已够用时记录 KEEP_BASELINE，继续整轮；缺训练后端则归为训练依赖受阻，仍完成冻结模型试验。
4. **验收线在看封存结果前冻结。** 初版要求几何/协议必备断言通过，直道可观测区的 P95 横偏较同扰动开环降低至少 30%，正负扰动均可收敛；可达工位先以连续三帧 ≤2.5 px 作对齐目标，同时报告独立的毫米误差。道路候选同时看 IoU、非道路误通行、越界/碰撞，验证集误通行率不高于冻结对照才能晋级。顶面报告各颜色/工作面/可见度的误选、漏检、中心 P95；正常场景中一直停车/一直 HOLD 算未完成。
5. **封存选手只比一次。** 开发/验证阶段最多三轮有依据的修复或训练，选择一个候选或保持冻结模型，然后一次性在封存组运行冻结对照和锁定版本。第一批建议 12 个可完成封存场景中至少 11 轮完赛，且全部场景错色/错槽释放、重复执行、碰撞、禁区侵入为 0。若对封存案例进行了针对性修改，则另建新的封存集。各个分母及有无刚体释放、使用精确/档位反馈、预设/视觉闭环行驶分别报出。以上门槛属于仿真试验约定。
6. **预算和结束。** 每版先测 6 组的磁盘与运行成本，估算完整批次，写入运行清单。默认三版开发上限、一次封存评估、100 轮耐久。没有改动且无新增证据时提前锁定当前最佳版本。耐久种子来自独立区间，运行前登记。主机可设墙钟/磁盘预算；达到预算保存精确断点并给出未完成清单，下一次同一命令接续。本地执行不依赖付费训练服务。

**生命周期。** 生成任务 → 原子领取 → 子进程运行 → 校验全部必需产物 → 登记结果与摘要 → 调度下一项。每个任务使用 campaign、suite、case、seed、variant、代码/模型/资产/配置哈希组成的键；开发和封存权限分开。队列使用带事务和租约的 SQLite 或等效设施，允许一个主调度器和有界数量的 worker。任务写入专属临时目录，验完再原子发布；使用独立 attempt_id 保留每次尝试。新进程以相同 campaign 重入时，校对状态、指纹和产物，复用已验证结果，回收过期租约。已完成的旧版本回执不得复用为新版本结果。

**异常策略。** 每 30 秒写心跳，根据冒烟的实测耗时设置不同作业的看门狗。案例错误保存第一处失败的前后帧并继续；基础设施故障用原种子最多重试两次，可降低并发或用 CPU 后备。后端变化须记入结果。持续失败只阻断确实依赖该数据的分支。磁盘不足先停止产生非必需预览或减少并发，保留原始证据与用户文件。监督进程可自动限次拉起崩溃的子进程；模拟动作超时与 worker 整场重启分层，后者从干净世界重算或从原子快照恢复。主机重开后用同一条 resume 命令；缺失外部依赖及部分完成必须在最终状态明示。

**证实可以无人看守。** 冒烟中程序主动中断一次指定 worker、损坏一份临时产物、丢弃一次已执行动作的回执；比较恢复前后已完成任务、物料账本、重复命令数与独立裁判结果。另设专用 STOP 文件，停机时写一致的断点。默认 full 会自动跑完 T13；还可实现 `--profile soak --max-episodes 100 --seed-start 10000` 单独追加更多种子，输出到新 campaign。无需外部定时任务或人工查看每个版本的界面。

**调度降级。** 为 stack、development_rounds、locked_rounds 按几何回执和刚体回执展开两个变体。physics_sweep 是刚体变体的强依赖；几何变体仍可完成抓放次序、通讯、遮挡与整轮评估。训练被跳过时 model_comparison 输出锁定基线的决策供下游使用。任何变体或封存样例因依赖缺失而跳过，都计入必跑未完成。执行器应有项目内的一键监督入口，在同一会话中自动拉起意外退出的调度器并接续同一 campaign；正常完成或主动 STOP 后退出，机器关机期间保存断点。

## 8　交付目录和最终判定

所有运行证据归入 `H/experiments/continuous-sim/<campaign>/`，建议索引如下。已有同义文件可直接复用：

| 产物 | 内容 |
| --- | --- |
| manifest.json、queue.sqlite、status.json | 提交/模型/资产 SHA、种子、拆分、运行环境、假设、反馈模式、资源及预算；状态查询应显示已完成/在跑/受阻/待跑和最近一次进度 |
| episodes/<case>/events.jsonl、metrics.json | 帧号/原始图或可重渲染索引、曝光对应姿态、观测年龄、TCP 与目标、分轴误差、所建议的执行机构、动作 ID 及其回执、仓位与场景耗时；裁判真值单独存放 |
| failures/、replay/、communication/ | 每种失败的第一处证据、预期/实测、重放命令；一条成功和一条含 UNKNOWN 的逐帧协议回放；展示导轨伸缩造成遮挡的近景，以及整轮短片/图序列 |
| comparison.json、report.md | T00–T13 各自的实际执行数量、成功/错误/合理拒判/未运行、覆盖率、分子分母；几何、物理、模块和整轮各自的结果，候选去留和与 R2 的可比范围 |

无人值守能力和算法质量各出一行结论。前者要求一条命令跑至终态报告并通过中断恢复试验；后者要求全部必跑专项实际执行、故障用例得到预期处理、封存通过线达到。队列结束但算法仍有失败时，交付报告照常生成，首屏列出未通过的模块与可复现案例。真实 STM32 固件调试、几何标定和赛场印证是后续独立工作。
