# CameraXY CPU 跟踪开销

a06 CNN1 在 K230 的 60 帧 USB 短测中，完整定位流程为 5.13 FPS。每帧 CPU 跟踪平均耗时 111.54 ms，包含 logits 转概率、网格预测与更新、候选排序和置信质量计算。RGB 转换及排列为 68.78 ms，KPU 为 5.75 ms。[原生记录](native-smoke-20261117/NATIVE_REPORT.md)

## 主机对照

基线为 `ca4cd7e836db62680be3051f0423bee4014c4162`。使用与板端测试相同的 [a06 CNN1 KModel](cloud/gray-map-pilot-a06/CNN1_KMODEL_REPORT.json)，将 25 组 Simulator logits 输入 R2 配置的 48 × 48 CPU 跟踪器。输入文件 SHA256 为 `b1c455507bc794b96e8e0ebd255c7eed571c09b9e5c402def5d5b515d31369cf`。每组含 2,304 个 logits。时间戳间隔固定为 0.2 秒，测试只计 `CameraXYTracker.update`，排除模型推理与采集。CPython 3.11.5 上以轮换顺序运行八次，取每次平均每帧耗时的中位数。

| 版本 | 主机 ms/帧 |
|---|---:|
| 基线 | 4.479 |
| 有限值检查与候选排序 | 3.953 |
| 置信质量距离计算 | 4.238 |
| 两项合并 | 3.602 |

主机平均每帧耗时的中位数下降 19.6%。默认最多五个候选时只保留当前排名，概率相同时沿用索引较大优先。置信质量扫描复用坐标计算，并保持原累加次序和 150/500 mm 阈值。48 × 48 网格继续使用原转移计算。

25 帧实际模型 Simulator logits 上，逐帧返回字段及完整后验数组与基线精确相等。另用固定种子的 110 帧输入分别验证默认和 800 mm/s 时间缩放软先验，两组皆精确相等，合计触发四次 LOST 后恢复。覆盖等概率、缺帧、NaN、低质量和长时间间隔。28 项主机回归通过，包括稀疏掩码候选和距离边界。

## 板端接续

优化后 MicroPython 耗时、整链 FPS、内存及长稳均为 **NOT RUN**。沿用独立测试目录及 a06 CNN1 权重，在设备空闲且相机身份明确时，用相同 logits 与时间戳对照跟踪器，再对照实际采集链路。记录版本、重复运行的阶段耗时 P50/P95、实际帧率、丢帧及退出 MMZ。定位准确率继续按真实相机光心 XY 验收。在准确率通过前，候选输出保留 `position_valid=false`。
