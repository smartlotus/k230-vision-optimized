# K230 旧 32 GB 卡数据分区修复

2026-11-18，北京时间。设备为庐山派 K230 1G，旧卡使用 CanMV `v1.8-36`。VS Code 的前序工作在本机项目中增加了数据卷保护。旧卡程序区可读，但板端报告 `/sdcard` 无可用块，`/data` 无总容量和可用容量。

通过 USB 读卡器确认旧卡为 32,010,928,128 字节。第三分区起始于 LBA 2,097,152，共 60,424,191 个逻辑扇区，原 MBR 类型为 FAT32 LBA，但分区引导扇区签名无效。采样可读到旧数据片段，因此保留了完整扇区备份。故障发生的具体时间与原因未确认。

本机备份位于 `C:/Users/28389/Downloads/k230-old-sd-repair/`。整卡镜像 `k230-old-32gb-full.img.gz` 压缩后为 3,363,529,963 字节，解压后的全部 32,010,928,128 字节 SHA-256 为 `a61ade8099f29fb9da05b9951bc36f268ddf8d1a09863bd9f847a271e8e12add`，与读取时计算的 SHA 一致。另有前 1 GiB 镜像和所修改脚本的独立原件。镜像和原卡数据留在本机。

在旧卡现有第三分区上新建 FAT32 文件系统，卷标 `K230DATA`。读卡器中显示为 `G:`，总容量 30,920,392,704 字节，改完输出路径后可用 30,920,245,248 字节。分区位置和长度一致，Windows 只读 `chkdsk` 通过，50 字节探针经关闭、重开和哈希核对通过。

首次检查以完整 MBR 哈希不变为条件，因此报告失败。逐字节比较格式化前后的前 1 GiB，确认 18 处差异仅涉及第三分区的 3 个旧式 CHS 字节和 11 个 FAT16 目录项的最后访问日期。分区的 LBA 边界、启动负载和程序文件内容一致。同步输出入口后，再次核对 `main.py`、`/bin/config.txt`、TopFace 和 RoadNet 模型哈希，与修复前一致。

已原位更新旧卡上的 6 个脚本，全部主机编译及最终读回通过。TopFace 显式入口写 `/data/logs/`，数据卷不可用时在启动相机前报错。拍照及数据采集示例写 `/data/captures/`，MP4 和 WAV 示例写 `/data/`。旧固件示例只调整输出路径。RoadNet 的报告目标仍由调用者指定。原 `/sdcard` 程序分区可用空间仍为 0。

旧卡重新装回 K230 后，从 COM3 核对固件仍为 `v1.8-36`，CanMV 设备显示 `data` 总量 30,920,392,704 字节。板端读回电脑写入的小文件并校验，另在 `/data` 新建 63 字节测试文件并逐字节读回。再次核对启动脚本、固件配置和 6 个输出脚本源码。当前未运行摄像头、编码器或识别程序。[板端验证收据](board-postflight.json)
