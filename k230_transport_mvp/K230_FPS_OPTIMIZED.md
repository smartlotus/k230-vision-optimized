# 约25FPS目标：电脑端优化版本

目标是每秒约25次新帧识别，即端到端约40ms/帧，不是重复显示缓存帧。
**当前未连接或上传K230，未验证25FPS。** 用户本轮明确只做电脑端。
分支 `ops/k230-fps`；基线 `4430306ae3dd8e637a5a0d504526959f2df68170`。
原有1120个跟踪文件全部保持原样；之前UART和物块跟踪优化版本也保留。

## 新代码

- `k230/tuning/live_optimized.py`：实时调参链独立副本，每帧完整识别，默认每3帧生成并刷新一次预览。不显示的帧不创建全帧遮罩、保留图和绘图用轮廓遮罩，不绘制轮廓。
- `vision/ellipse_native_optimized.py`：原生拟合后的标量验证流式处理全部轮廓点，避免再复制完整坐标列表；不创建无用的128点拟合样本；每轮复用轴平方，缓存最多3个形态学核。
- `run_live_workbench_optimized.py`：独立启动入口，使用 `/sdcard/transport_mvp_optimized`。旧目录、旧入口和main.py不变。
- `tools/benchmark_live_optimized.py`：可复现主机图像操作/耗时/临时分配对照。

完整边界、残差、角度覆盖、内部填充、裁边、ROI、颜色阈值、候选上限和新鲜帧语义不变。
不使用上一帧几何，不轮流漏扫颜色，不降低识别分辨率，不把草稿识别冒充已应用配置。
纸靶和黑色边缘路径继续用保留实现；向量边界开关同时传到新旧边界模块。
默认标量模式，不自动假设板端支持ulab。默认每3帧预览意味着识别25FPS时预览约8.3FPS；可显式设置preview_every=1恢复逐帧预览。

## 当前瓶颈证据

历史2026-11-10板端记录的前三个窗口识别约2.53–2.64FPS，view均值289–333ms，JPEG约23ms。
这些是历史场景，不是本轮实测；来源和SHA见 `evidence/k230-fps/historical-budget.json`。
历史view已远超40ms预算，仅降低JPEG刷新频率不足以保证25FPS。

新日志保留原协议版本，并增加performance_variant、target_recognition_fps、target_frame_budget_ms、
current_view_stages_ms和window.target_fps_met。分阶段计时包括纸靶、批量颜色初筛、各色轮廓、黑色边缘补检及预览图像。
current_view_stages_ms是当前单帧耗时；原window.stages仍是窗口统计。
target_fps_met要求窗口至少1秒、无累计处理错误且实际识别率达到25；它不代表识别准确率验收。

## 主机验证

全套469项测试通过，无跳过。新增8项覆盖：

- 原生/标量/向量完整边界差分（16至4096点）、孔洞、噪声、形态学核及超限拒绝。
- 不显示帧与显示帧的TOP、RING物块几何结果一致。
- 实际main循环6张新帧均识别，只显示第3、6帧，草稿和active保持不变。
- 轮廓临时内存上界、核缓存上界、可选计时不改变几何。

合成640×360单椭圆，250次调用的显式复制像素量：旧版119,662,500，新版不显示帧2,231,250，减少98.1%。
按每3帧显示一次估算，该样本的平均显式复制像素量减少65.4%；不是总堆内存测量。
50次调用的五轮中位耗时：旧版24.921ms、新版显示帧24.928ms、新版不显示帧15.364ms。
显示帧基本无加速，不显示帧约降低38.3%；这些时间不含真实摄像头、LAB初筛、JPEG和LCD开销。
4096点原生标量验证的Python峰值临时分配从440,224降到2,208字节（约99.5%）；不含输入轮廓及原生图像缓冲。
不把上述主机结果换算为板端FPS。

证据目录 `evidence/k230-fps/`：tests.json/.log、benchmark.json、preservation.json、historical-budget.json。
复现：`python -B -X utf8 -m tools.benchmark_live_optimized --output evidence/k230-fps/benchmark.json`。

## 后续板端验收入口（本轮不执行）

先核对占用、运行状态、当前源文件、相机映射和active/draft；保存可恢复快照。
新版本需完整依赖树和经过核验的配置，不能只复制新入口；独立profile/mailbox路径不能冒充旧工作台会话。
不要为测试重置用户草稿或覆盖已保存配置。新入口检测到已缓存的k230模块会拒绝混装。
有界main调用可用max_frames，并显式传入经核验的initial_state、当前颜色集合、向量开关和preview_every。
相同视野下分别统计识别、显示、错误、检测结果及各阶段耗时；至少多个完整窗口确认约25FPS，同时核对目标丢失、裁边和误检。
若纸靶/黑色边缘仍超过预算，应依据分阶段证据继续优化，不能用跳过识别或放宽几何门限换取达标。
