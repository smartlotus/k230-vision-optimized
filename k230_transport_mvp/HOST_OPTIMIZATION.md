# 项目结构与本轮优化（2026-11-11）

基线为 `ops/live-tuning` 的 `c4fcbf2675eb45d6eb74241fe28f1bb12c072039`。
改动位于独立工作区 `k230worker-optimize`、分支 `ops/host-hashing`。

## 项目结构

- `vision/`：颜色、顶面、圆环、车道、二维码候选与稳定跟踪，保留像素坐标和有效性信息。
- `k230/`：摄像头、视觉适配、调参运行时和串口适配；`k230-workbench/` 为同仓电脑端 VS Code 工作台。
- `core/`、`sim/`：任务解析、规划、执行状态及离线场景模拟。
- `ports/`、`stm32/`：识别结果协议与接收实现；主机协议测试不代表真实串口或车辆验收。
- `tools/material_*`、训练/导出工具：源图身份校验、人工审核、场景分组、训练与模型转换约束。
- `tests/`、`evidence/`：回归测试与历史证据；最新状态从 `.ops/PROJECT.md` 和 OPS 交接读取，README 中旧实时描述不能当作当前硬件状态。

最近交接记录为 7 张批准图、17 个顶面框，首次试训 1 epoch / 4 次 optimizer 更新。
验证集只有 2 张红图，识别效果未验收；困难图复核、任务 kmodel、AI2D、板端 A/B 和整车验证仍待完成。
本轮没有修改这些数据或重新训练。

## 修改与验证

新增 `tools/file_integrity.py`，以 64 KiB 缓冲区计算文件 SHA256。
训练权重/产物校验、ONNX 文件摘要及源文件复核共用该函数。
不缓存摘要；每次重读当前文件，读错误继续抛出，原有篡改拒绝和身份绑定保持有效。
需要解码的 RGB565 数据仍完整读取；本次不改变图像解码或模型加载内存。

全套 427 项主机测试通过，无跳过，包括新增的空文件、分块边界、同长度修改、缺失文件和内存上界测试。
测试命令及源文件指纹见 `evidence/host-hashing/tests.json`，输出见同名 `.log`。

`evidence/host-hashing/benchmark.json` 对比 1、16、64 MiB 合成二进制文件：
全部摘要一致，流式路径 Python 峰值分配均为 75,157 字节；
64 MiB 的原路径峰值为 67,117,530 字节。测量使用 tracemalloc，不是进程总 RSS。
计时仅为单次本机观测，不作为稳定吞吐承诺，也不代表 K230 帧率或识别精度。

没有连接硬件、修改用户标注、上传算法或启用 UART。原工作区暂存内容保持不变。
本分支是独立交付，尚未合入 `ops/live-tuning` 或主线。
